// 03. SELECTED WORK & PROOF

實作證明 · 實戰案例深度剖析

不談空洞理論。以下展示真實處理過的複雜工程案例：背景、痛點、由果溯因的排查路徑與最終交付成果。

CASE 01 · DATABASE RE-INDEXING & LOCK HEALING PostgreSQL / 分布式平帳 / 核心金融資料庫

百萬級流水高併發死鎖（Deadlock）消除與查詢效能 40 倍提升

【問題與痛點】 尖峰時段錢包交易與報表查詢衝突，資料庫頻繁觸發 Deadlock 報錯，CPU 飆高至 98%，API 響應延遲高達 3.8 秒。
【由果溯因拆解】 透過 `pg_stat_activity` 與慢查詢鎖追蹤，發現複合索引鍵順序顛倒導致不必要的全表掃描，且交易更新鎖未依照固定 ID 順序排序。
【落地解決方案】 重構 B-Tree 覆蓋索引、將交易鎖統一改為 Serializable 平帳鎖，並導入 Read-Replica 分流報表查詢。
交付成果：Deadlock 發生率降為 0，P99 查詢響應時間由 3,800ms 降至 85ms，CPU 尖峰負載平滑在 22% 以下。 40x FASTER
CASE 02 · ENTERPRISE PIPELINE & AUTOMATION FastAPI / Python / Redis Stream / Docker

跨異質系統全自動 ETL 與 0 遺漏數據清洗中台

【問題與痛點】 企業內部 4 個舊系統數據格式不一，每日需耗費 2 名工程師手動核對平帳與匯入，偶發性網路超時導致數據漏單。
【由果溯因拆解】 分析傳輸封包與超時節點，發現缺乏持久化隊列緩衝，且舊系統接口未實作冪等性識別碼（Idempotency-Key）。
【落地解決方案】 以 FastAPI 打造微服務網關，引入 Durable Outbox + Redis 隊列，實作自動重試與死信隊列（DLT），並以 Docker 容器化交付。
交付成果：人工對帳工時徹底歸零，數據拋轉成功率達到 99.999%，異常情況 3 秒內自動推送 Telegram 警報。 100% AUTOMATED
CASE 03 · CLOUD ARCHITECTURE & ZERO-EXPOSURE MESH Linux / Cloudflare Tunnel / Oracle Cloud / Zero Trust

海外雲端基礎設施 0 端口暴露與全球防探測加密隧道

【問題與痛點】 管理控制台與內部 API 直接暴露於公網，每日遭遇數萬次惡意端口掃描與爆破攻擊，存在重大資安與合規隱患。
【由果溯因拆解】 梳理外部流量路徑，傳統作法開公網 IP + 防火牆白名單維護成本極高，且動態 IP 容易誤鎖管理員。
【落地解決方案】 封閉雲端伺服器全部入口端口（0-Ingress Ports），部署 Cloudflare Tunnel QUIC 專線，結合自訂網域實現端到端 TLS 加密穿透。
交付成果：外網掃描面徹底收縮為零，伺服器真實 IP 100% 隱匿，連線延遲大幅壓降並享有全球 CDN 加速。 ZERO ATTACK SURFACE
